# Labs

The **Labs** settings page holds features that **you can turn on, but that are still experimental**. They are open to you — switch one on whenever you like. You just want to know what "experimental" means first.

## What experimental means

- **Behaviour can change.** The same feature working differently in the next version is normal.
- **It may be slower or cost more.** Some of these have the assistant think in more rounds, or call more tools.
- **Support for diagnosing problems is limited.** If something misbehaves, turn it off and try again — that usually resolves it.

What does not change: **permissions and audit on data access are never relaxed because an experimental feature is on.** That holds in every mode.

## What is there

**Code mode** — lets the assistant work by writing code rather than calling tools step by step. Noticeably better at bulk, repetitive work.

**Multi-agent collaboration** — splits a large task across several assistants working in parallel, then combines the results. Clearly faster when the task is big; pure overhead when it is small.

**Tool search** — when many tools are available, lets the assistant search and choose rather than reading the whole list. Saves a good deal of context.

**Loop detection** — interrupts the assistant when it notices it is going in circles. Usually harmless to leave on.

**Isolated workspace** — gives the assistant its own working copy, so changes never touch your real content until you have checked them and merged them back.

**Cloud work environments** — runs execution in a separate environment. This one is **not connected yet**; see [Not open yet](/not-yet-open).

## How to use them

Turn on one at a time and live with it for a few days. Turning on several at once makes it impossible to tell which one caused a problem.

If one turns out to be genuinely useful, **tell your administrator** — that feedback is how an experimental feature becomes a default.
