# Not open yet

The assistant runs on a general-purpose agent substrate, so the interface shows some features that **come with the substrate but are not connected in this deployment**. They have not been cancelled — they are **not open yet**.

On these pages you will typically find that the page opens, but nothing connects, nothing saves, or buttons do nothing.

## What they are

**Desktop and mobile apps**
The substrate supports macOS / Windows / Linux desktop apps and iOS / Android mobile apps. Only **browser access** is offered here.

**Device nodes and voice**
Attaching a computer, a camera, or a voice endpoint as a "node" of the assistant. Not open; the pairing entry points that go with it are unavailable.

**External chat channels**
Talking to the assistant from Slack, Telegram, and similar tools. For now the assistant's own interface is the only place.

**Browser extension**
The substrate ships a companion extension for handing the current web page to the assistant. Not provided here.

**Device pairing**
Most of the above require pairing a device first. The pairing entry point is visible, but there is nothing to pair with yet.

## Why not yet

Most of these require opening another route through your organization's network boundary. Each one has to be assessed separately for how it joins single sign-on and how it gets recorded — **taking a shortcut around your organization's existing identity and governance is not an option**.

So the order is governance first, capability second, not the other way round.

## If you need one of them

**Tell your organization's administrator**, and describe the situation — when you would use it, and what work it would let you finish.

That feedback is what sets priority. Nothing above has been ruled out; it simply has not come up the queue yet, and **someone actually needing it** is the most effective way to move it.
