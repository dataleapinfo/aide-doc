# 尚未开放的能力

助手运行在一套通用的智能体底座上,界面里因此会出现一些**底座自带、但当前部署还没有接通**的功能。它们不是被取消了,是**还没开**。

碰到这些页面,现象通常是:能打开,但连不上、配不成、或者按钮点了没反应。

## 有哪些

**桌面端与手机端应用**
底座支持 macOS / Windows / Linux 桌面端和 iOS / Android 手机端。当前只提供**浏览器访问**。

**设备节点与语音**
把一台电脑、一个摄像头或一个语音端接进来当作助手的「节点」。当前未开放,相关的配对入口也不可用。

**外部聊天渠道**
从 Slack、Telegram 等外部聊天工具里直接跟助手对话。当前只能在助手自己的界面里用。

**浏览器扩展**
底座提供一个配套扩展,用来把当前网页内容交给助手。当前未提供。

**设备配对**
上面几项大多需要先配对设备。配对入口在界面上可见,但当前没有可配对的目标。

## 为什么先不开

这些能力大多要在你所在组织的网络边界上新开一条访问通路。每开一条都要单独评估怎么接入统一登录、怎么留痕 —— **不能为了省事绕开组织现有的身份与治理**。

所以顺序是先把治理接通,再开能力,而不是反过来。

## 如果你需要其中某一项

**告诉你所在组织的管理员**,并说明你的使用场景 —— 你想在什么情况下、用它完成什么工作。

这类反馈是排优先级的依据。上面这些没有被否决,只是还没排到,而**有人真的要用**是最有效的推动方式。
